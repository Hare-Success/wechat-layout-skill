# 样式下沉到模板 + tech-ai 改名 + growth 主题落地

## Context

当前主题系统是"半成品"：卡片/引用/代码块等样式在主题模板里，但 H1-H3 标题样式、列表项样式、行内代码/加粗样式全部硬编码在 `scripts/renderer.py`（约 108-213 行）。用户目标是 4+ 个主题（目录即主题），按现状新主题只能是换色复制品。本次改造把全部视觉决策下沉到主题模板，让"加主题 = 加目录改 HTML"，并用第二套配色（layout-parameters.md 的 增长/商业：#059669/#F0FDF4）落地 growth 主题做架构验收。已确认：主题 1 同时改名为 **tech-ai**。

## 目标组件契约（renderer ↔ 主题的接口）

一个主题必须提供 **17 个组件**（`components/*.html`，`$var` 占位符，仅 string.Template 语法）：

| 组件 | 变量 | 说明 |
|---|---|---|
| article | $content | 外层容器 |
| heading-h1 / h2 / h3 | $content（h2 另有 $part_number） | 三级标题，H4-H6 复用 h3 |
| paragraph / quote | $content | 段落/引用 |
| code | $content, $lang | 代码块 |
| list | $items | 列表容器 |
| list-item-ul | $content | 无序项（圆点符号写死在模板内） |
| list-item-ol | $content, $number | 有序项 |
| card / warning | $title, $content | 卡片 |
| highlight / divider / image_placeholder | $content（后两者无变量） | 特殊块 |
| inline-code / strong | $content | 行内代码/加粗的 span 包装 |

所有模板可额外引用自动注入的通用变量：`$primary`、`$light_bg`、`$body_color`、`$body_font_size`、`$body_line_height`（后三个来自 theme.json，目前是死配置，本次激活）。

renderer 保留的只有**语义**：块类型→模板名分发、H2 的 Part 计数、有序列表起始编号、卡片 kind→模板映射与默认标题、HTML 转义与行内标记替换顺序。

## 实施步骤

### 1. 建立回归基线（改代码之前）
- 在系统临时目录（不进仓库）写一个覆盖全部块类型的样例 md：H1/H2/H3、含行内代码/加粗/下划线的段落、引用、代码块、有序+无序列表、:::card / :::tip / :::highlight / :::warning、分割线、图片占位。
- 跑 `python scripts/render.py <样例> --theme testModel -o <临时>/baseline.html --ast <临时>/baseline.ast.json` 留底。

### 2. `scripts/theme_loader.py`：主题契约校验
- 新增 `REQUIRED_COMPONENTS` 常量（上述 17 个名字）。
- `load_theme` 加载完成后校验缺失组件，缺失时抛出**列出具体缺哪些文件**的明确错误（给主题作者可读的报错）。

### 3. `scripts/renderer.py`：样式下沉（核心）
- `_template()` 的 defaults 扩展 body_color / body_font_size / body_line_height（带缺省值，theme.json 未配时兜底）；`render()` 的 article 替换同步注入。
- `_render_heading()` 缩成 level→模板名映射（1→heading-h1，2→heading-h2，3-6→heading-h3），只传 $content 和 H2 的 $part_number；删掉 `_part_label()`（H2 在 render() 里总能拿到编号）。
- `_unordered_list_item` → `_template(theme, "list-item-ul", content=...)`；`_ordered_list_item` → `_template(theme, "list-item-ol", content=..., number=...)`。
- `_inline()`：行内代码、加粗的 span 改从 `inline-code` / `strong` 模板取（样式字符串原样搬进模板）；**先转义、行内代码最先替换**的顺序不动。
- 卡片 kind→模板映射、`_default_card_title()` 保持不变。

### 4. 主题 1：testModel → tech-ai
- `mv assets/themes/testModel assets/themes/tech-ai`（普通 mv，不动 git index；git 提交时自动识别 rename）。
- `theme.json`：name → tech-ai，display_name → Tech AI。
- `scripts/render.py`：`--theme` 默认值 → tech-ai。
- 模板变更：**删 heading.html**；新增 7 个（heading-h1/h2/h3、list-item-ul/ol、inline-code、strong），内容 = renderer.py 现有样式**逐字节原样搬运**（H2 胶囊内文字改为 `Part $part_number`，颜色用 `$primary`）；article.html / paragraph.html 中写死的 #333333/15px/1.9 换成 $body_* 变量（tech-ai 的 theme.json 值相同，输出不变）。

### 5. 主题 2：growth（纯新增，验收架构）
- `assets/themes/growth/theme.json`：primary #059669、light_bg #F0FDF4、body_* 同规格。
- 17 个组件全量提供，与 tech-ai 同名但**结构性差异化**（这正是验证点）：H1 左对齐+左侧色条（vs 居中+底部横条）；H2 用「$part_number」章节号+色条风格（无 Part 胶囊）；卡片改整卡浅底+圆角（vs 左边框线）；列表符号换样式；引用块浅绿底。
- 全部遵守 wechat_rules（section 容器、纯内联样式、无 flex/grid/position/gradient/h1-h6）。

### 6. `references/theme-contract.md`（新契约文档）
17 组件清单与各自变量、通用自动注入变量、规则红线（引 wechat-html-rules.md）、"新增主题三步法"（复制目录→改 HTML→validate_template 校验）。

### 7. README.md
补一行多主题用法示例（`--theme growth`）。

## 验证

1. **字节级回归**：改造后对同一样例重跑 `--theme tech-ai`，diff baseline.html 必须为空（AST JSON 同样 diff）。
2. **规则校验**：`python scripts/validate_template.py assets/themes/tech-ai/` 和 `assets/themes/growth/` 全部通过。
3. **缺组件报错**：临时改名 growth 一个组件文件调 `load_theme("growth")`，确认报错列出缺失文件名（测完还原）。
4. **视觉验收**：growth 主题渲染成功后，浏览器打开 tech-ai 与 growth 两份 HTML 截图对比，确认风格差异明显且无破版。
